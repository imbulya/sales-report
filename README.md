# Расчёт заказов и выручки по артикулам

Скрипт читает выгрузку заказов `sales.csv` и для каждой пары «артикул - день» считает число заказов и выручку. Результат сохраняется в файл `daily_by_sku.csv`.

## Как запустить

Все команды вводятся в командной строке (на Windows - `cmd`, на Mac - «Терминал»). Дальше везде пишу `python`; на Mac вместо него нужно `python3`, а вместо `pip` - `pip3`.

1. **Проверьте, что установлен Python.** Введите `python --version`. Если видите номер версии (3.8 или новее) - всё в порядке. Если команда не найдена, скачайте Python с python.org и при установке отметьте галочку «Add Python to PATH».
2. **Подготовьте папку.** Скачайте репозиторий и откройте его папку. Положите рядом со скриптами файл с данными и назовите его именно `sales.csv` (в репозитории его нет). Внутри папки должны лежать `daily_by_sku.py`, `check.py`, `explore.py` и `sales.csv`.
3. **Откройте командную строку в этой папке.** В Windows: откройте папку в проводнике, кликните в адресную строку, введите `cmd` и нажмите Enter. На Mac: введите `cd ` с пробелом, перетащите папку в окно терминала и нажмите Enter.
4. **Запустите расчёт:**
   ```
   python daily_by_sku.py
   ```
   Для расчёта ничего устанавливать не нужно, он использует только стандартную библиотеку Python. Если всё прошло успешно, в консоли появится строка вида `Заказов: 13798, строк в daily_by_sku.csv: 631`.
5. **Заберите результат.** Файл `daily_by_sku.csv` появится в той же папке. Его можно открыть в Excel. В нём четыре колонки: `sku, order_date, orders, revenue`.

Два других скрипта нужны только для проверки и поиска проблем. Им требуется pandas, который ставится один раз командой `pip install pandas`:
- `python check.py` - сверяет результат с независимым расчётом. При успехе выводит `OK` и итоги.
- `python explore.py` - показывает проблемные строки в исходных данных.

Если нужны другие пути к файлам, их можно передать аргументами: `python daily_by_sku.py путь/к/sales.csv путь/к/результату.csv`.

## Как проверяла, что расчёт верный

Я посчитала то же самое вторым способом и сравнила. `check.py` берёт исходный файл, убирает дубли, приводит статусы к единому виду и группирует данные через pandas, после чего сравнивает получившуюся таблицу с результатом основного скрипта целиком. Таблицы совпали.

Кроме того, я сверила контрольные цифры:
- В файле 13 858 строк, из них 60 дублей, то есть уникальных заказов 13 798. Сумма колонки `orders` в результате равна 13 798.
- Общая выручка в результате - 10 276 540 руб. Отдельно я посчитала её простым циклом по уникальным заказам, без группировки, и получила то же число.
- В результате нет повторяющихся пар «артикул - день», строки отсортированы по артикулу, затем по дате.

Чтобы убедиться, что исправление данных вообще влияет на итог, я посчитала выручку без него: если не убирать дубли и сравнивать статусы как есть, получается 10 296 800 руб., то есть на 20 260 руб. больше.

## Какие проблемы нашла в данных

**Дубли.** В выгрузке 60 строк, которые полностью повторяют другие строки, в том числе по номеру заказа. Строк с одним номером, но разными данными нет, поэтому выбирать между версиями не пришлось. Заказ я считаю один раз, по первому вхождению.

**Разные написания статуса.** Всего таких строк 35: `Delivered`, `DELIVERED`, `delivered ` (с пробелом на конце), `Cancelled`, `CANCELLED` и `canceled` (с одной буквой l). Для компьютера это разные слова, и без исправления часть выкупленных заказов не попала бы в выручку. Я убираю пробелы, перевожу всё в нижний регистр, а `canceled` считаю таким же статусом, как `cancelled`.

**Пропущенное количество.** В четырёх строках пусто поле `quantity`. Все четыре заказа отменённые, поэтому в `orders` они учитываются, а в выручку не входят, и на результат это не влияет. Если бы пустое количество встретилось у выкупленного заказа, скрипт остановился бы с ошибкой, а не стал угадывать.

Остальное проверила и проблем не нашла: даты корректны и лежат в диапазоне с 2026-08-17 по 2026-10-11, артикулы записаны единообразно, у каждого артикула одна цена. Если в статусе появится незнакомое слово, скрипт остановится с понятным сообщением.

## Какие ИИ-ассистенты использовала и что пришлось исправить

Я работала с Claude (Claude Code). Работу я разбила на три шага и на каждом дала ассистенту отдельное задание.

**Шаг 1. Поиск проблем в данных (`explore.py`).** Задание было такое:

> Напиши скрипт на Python с использованием pandas, который читает sales.csv и находит проблемные строки. Читай все колонки как текст (dtype=str, keep_default_na=False), чтобы пустые значения и пробелы не терялись. Критерии корректной строки: order_id - только цифры; order_date - дата в формате ГГГГ-ММ-ДД; sku - вида UYT-0000; quantity - целое число больше 0; price - целое число больше 0; status - ровно delivered или cancelled. Найди: полные дубли строк, повторы order_id, пустые значения и значения, не подходящие под критерии. Для каждой проблемы выведи количество и несколько примеров строк. Файл не изменяй, скрипт должен только печатать результат.

**Шаг 2. Расчёт (`daily_by_sku.py`).** Задание:

> Напиши скрипт на Python (только стандартная библиотека), который читает sales.csv (запятая, UTF-8) и сохраняет daily_by_sku.csv с колонками sku, order_date, orders, revenue. orders - число заказов по артикулу за день, включая отменённые. revenue - сумма quantity × price за день только по заказам со статусом delivered. Каждый заказ считай один раз, даже если его строка встретилась дважды. Перед сравнением приведи статусы к единому виду (регистр, пробелы, canceled/cancelled). Если статус неизвестный или у выкупленного заказа нет количества - остановись с понятной ошибкой, а не считай молча. Строки отсортируй по sku, затем по дате. Пути к файлам бери из аргументов командной строки, по умолчанию sales.csv и daily_by_sku.csv. Код сделай коротким и читаемым, с комментариями к неочевидным местам.

**Шаг 3. Проверка (`check.py`).** Ход проверки я описала сама:

> Напиши проверочный скрипт, который не повторяет логику основного, а считает то же самое другим способом через pandas: прочитай sales.csv, удали дубли строк, приведи статусы к единому виду, посчитай выручку по каждой строке и сгруппируй по sku и order_date. Сравни полученную таблицу с daily_by_sku.csv целиком. Дополнительно проверь контрольные цифры: сумма колонки orders равна числу уникальных order_id в исходном файле; номера заказов после удаления дублей уникальны; в результате нет повторяющихся пар sku и order_date; строки отсортированы по sku, затем по дате. Если что-то не сходится - остановись с понятным сообщением; если всё сходится - выведи OK, число строк, число заказов и общую выручку.

## Что не доделано и в чём не уверена

- Слово `canceled` я считаю опечаткой от `cancelled`, то есть отменённым заказом. В условии об этом прямо не сказано, и если в контрольном расчёте оно трактуется иначе, результат разойдётся.
- Дубли убираю по номеру заказа и оставляю первую строку. Это безопасно только потому, что в этой выгрузке дубли полностью одинаковые. Если бы у одного номера были разные данные, правило пришлось бы уточнять.
